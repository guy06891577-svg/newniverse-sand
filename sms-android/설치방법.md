# 뉴니버스 문자 v11 (시험판) 설치 방법
안내 페이지: https://guy06891577-svg.github.io/newniverse-sand/apk/sms.html
내려받기: https://guy06891577-svg.github.io/newniverse-sand/apk/newniverse-sms-v11-test.apk
패키지 kr.newniverse.sms · 버전 11-test (versionCode 11) · 런처·전화와 같은 뉴니버스 릴리스 서명

1. Play 프로텍트 검사 잠시 끄기 → 내려받아 설치(이전 버전이 있으면 덮어 깔기) → 다시 켜기.
2. 뉴니버스 문자 열기 → SMS·연락처·알림 허용.
   허용 창이 안 뜨면(제한된 설정): 앱 안내의 "앱 정보 열기" → ⋮ → "제한된 설정 허용" → 돌아와 "다시 시도".
3. 기본 문자 앱: 목록 ⋮ → "기본 문자 앱으로 설정". 되돌리기: 설정 › 애플리케이션 › 기본 앱 선택 › SMS 앱 › 메시지.

권한: READ_SMS(목록·대화·검색), SEND_SMS(보내기), RECEIVE_SMS(새 문자 알림·SMS_DELIVER 수신), RECEIVE_MMS·RECEIVE_WAP_PUSH(기본 앱 자격),
READ_CONTACTS(이름 표시·받는 사람 찾기), POST_NOTIFICATIONS, VIBRATE, READ_CALENDAR/WRITE_CALENDAR(처음 한 번, 설정에서 끄기). 인터넷 권한 없음.
기본 SMS 앱 자격(ROLE_SMS): SMS_DELIVER 리시버(BROADCAST_SMS), WAP_PUSH_DELIVER 리시버(BROADCAST_WAP_PUSH, application/vnd.wap.mms-message),
RESPOND_VIA_MESSAGE 서비스(SEND_RESPOND_VIA_MESSAGE), SEND/SENDTO 액티비티(sms·smsto·mms·mmsto).

v6 달력 읽기: ApptParser.norm 이 줄바꿈(CRLF·CR·U+2028)·유니코드 공백(NBSP 등)·0폭 글자·전각(：～．（）０-９)·물결표(〜∼)·동그라미(⚬◯◦●◎ㅇ)를 정리하고, 동그라미·‘일시:/장소:/주제:…’ 앞에서 줄을 나눔(줄바꿈 없는 한 줄 문자도 읽음). 일시 줄: ‘일시’(콜론 없어도) 뒤에 날짜(YYYY. M. D. / M월 D일 / M/D) + 시각(HH:MM / 오후 N시 / 별도 ‘시간:’ 줄), 시각 없으면 하루 종일. 진단에 막힌 단계(parse:no-date · deadline-only · no-datetime-line · past), 설정 › 달력 등록 기록 › ‘마지막 문자 다시 읽기’(AutoCal.reread: 받은 SMS·장문 중 날짜 있는 최신 문자로 같은 단계를 다시 돌림, 본문 저장 없음).

v5 달력: 학교 안내문 등 ‘○ 일시:/장소:/주제:’ 줄과 점 찍힌 날짜(2026. 11. 27.(금) 16:00, 11. 27.)를 읽음. 마감일(…까지)·‘신청 기간’ 줄의 날짜는 일정에서 제외. 제목=[이름표]+주제, 장소는 달력 일정의 장소 칸. 학교·학원·교육청 이름표는 보낸 번호가 주소록에 있거나 일반 전화(0xx)면 믿음(병원·보건소·교육청 이름표는 그대로). 신청·모집·선착순·폼 안내는 자동으로 넣지 않고 ‘달력에 넣을까요?’ 알림(넣기/아니요), 확정된 예약은 자동+취소. 자동 넣기는 끈 적이 없고 달력 권한이 있으면 켜진 것으로 봄. 달력 앱(제공자)이 없거나 쓰기가 실패하면 알림, 보여 줄 앱이 없으면 한 번만 알림. 설정 › 달력 등록 기록(단계·이유 코드, 본문·번호 없음). 장문(MMS) 저장 뒤 AutoCal.onSms 가 같은 경로로 호출됨.

v4 장문·사진(MMS/LMS) 받기: 기본 앱일 때 WAP_PUSH_DELIVER(application/vnd.wap.mms-message) 의 intent "data" = M-Notification.ind 를 MmsPdu 로 읽음(트랜잭션 ID·Content-Location·보낸 사람·제목·크기) → 다시 받기용으로 앱 안 SharedPreferences(nv_mms_pending)에 기억 → SmsManager(구독 번호별).downloadMultimediaMessage(위치, content://kr.newniverse.sms.mmsfile/<키>-<번>.pdu, null, MmsResultReceiver 로 가는 PendingIntent(FLAG_MUTABLE, HTTP 상태 받기)). 파일 통로 MmsFileProvider 는 exported=false·grantUriPermissions, com.android.phone·com.android.mms.service 에만 쓰기 허락.
결과 RESULT_OK → M-Retrieve.conf 를 MmsPdu 로 읽음(multipart, text/plain 글자셋 EUC-KR 38·KS_C_5601 36 → CP949, UTF-8 106, UCS-2 1000, 글자셋 없으면 UTF-8 → CP949 추측; 제목·보낸/받는 사람·날짜·Message-ID·사진 조각) → content://mms/inbox 에 저장(msg_box=1, m_type=132, date=받은 시각(초), date_sent, thread_id=getOrCreateThreadId(보낸 사람), sub=원래 바이트 ISO 문자열+sub_cs, m_id·tr_id·ct_l·text_only) + content://mms/<id>/part(글은 text 칸·chset=106, 사진은 openOutputStream) + /addr(137 보낸 사람, 151 받는 사람, 130 참조). 같은 m_id/tr_id 가 이미 있으면 다시 넣지 않음(dup). 저장 뒤 M-NotifyResp.ind(Retrieved 0x81) 를 sendMultimediaMessage 로 보냄(실패해도 문자는 저장됨). 알림(보낸 사람 이름 + 글 미리보기, 사진이면 [사진 N장]) · 런처 신호 · 달력 자동 넣기.
실패: 일시적 오류(1·3·4·5·6·8·103)는 한 번 자동으로 다시, 그래도 안 되면 ‘장문을 받지 못했어요’ 알림(이유 + 다시 받기 단추). 설정 › 장문·사진(MMS) 받기 기록: 마지막 도착 신호 시각, 상태, 오류 번호·쉬운 말, HTTP 상태, 저장 여부, NotifyResp 결과, 못 받은 장문 수 + 다시 받기. 본문·번호 없음.
목록·대화·검색은 MsgMerge 로 SMS+MMS 를 날짜 순으로 합침(MMS date 초→밀리초). FeedProvider recent 는 장문 받은 편지함 글(제목+본문, MmsLogic.feedText)도 FeedFilter 로 골라 함께 넘김(id 음수, mms:true). 보내기(MMS 보내기)는 아직 없음.

v3 받은 문자 저장: 기본 앱일 때 SMS_DELIVER 에서 Inbox 에 넣음(type=INBOX, thread_id=getOrCreateThreadId, subscription 은 long). 실패하면 최소 칸으로 다시 시도. 반환 URI 를 확인하고, 실패하면 ‘문자를 저장하지 못했어요’ 알림. goAsync. 여러 PDU 본문을 한 통으로 이어 붙임. 기본 앱이면 SMS_RECEIVED 가 1.5초 뒤 중복 없이 한 번 더 넣기(안전망). content://sms ContentObserver 로 목록 새로 고침. getThreads 는 {ok,err,list} — 읽기 실패는 빈 목록이 아니라 오류 화면. 설정 › 받은 문자 저장 기록: 시각, 저장 결과/예외 종류, inbox 개수, 기본 앱, 권한, 런처 마지막 조회(메서드·행 수). 본문·번호·비밀 없음.

홈 카드(런처): 이 앱이 기본 문자 앱이고 런처 설정 「문자 속 할 일 카드」를 켠 뒤에만 우주에 저절로 뜸. 저절로 뜨는 건 오늘·내일 택배·예약과 방금 온 인증번호(최대 2장). 며칠 뒤 예약은 홈에 「병원 예약 언제야」로 물으면 됨. 일상 짧은 문자는 카드가 안 됨. 안 보이면 이 앱 설정의 ‘런처의 마지막 조회’를 확인.
